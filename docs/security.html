Security and release verification

Open File Backup Manager reads and writes only the local paths selected for a backup. Mirror mode can remove destination-only items after a successful copy and source recheck, but only if the user confirms the exact deletion preview. These boundaries are enforced by the desktop process as well as the interface.

No antivirus result, checksum, signature, open-source license, or build attestation proves software is harmless. Each check answers a different question.

Verify the actual download

Get the installer and SHA256SUMS.txt from the same official release. Compare the full digest in PowerShell:

Get-FileHash .\Open-File-Backup-Manager-Setup.exe -Algorithm SHA256
Get-AuthenticodeSignature .\Open-File-Backup-Manager-Setup.exe

For build provenance, use GitHub CLI with the downloaded installer:

gh attestation verify .\Open-File-Backup-Manager-Setup.exe --repo johnkai-kai/Open-File-Backup-Manager

Check the result against the specific release's source revision and workflow. An unsigned installer may show an unrecognized-publisher message in Windows. Do not disable antivirus or system protections to run it.

Runtime boundaries

  • Robocopy is the sole transfer backend. The app invokes the Windows executable with an argument array, not through a command shell, and does not bundle a Microsoft executable or fallback copy engine.
  • Root links, unmatched destination links, drive-root destinations, protected application paths, ambiguous device names, and destructive path overlaps are rejected. Nested source links are skipped without following their targets; matching destination content is preserved.
  • Robocopy's list-only mode previews source and destination changes. The app validates paths and repeats that preview before copying and before confirmed mirror deletion. A failed copy, cancellation, or changed source blocks deletion. Preview tokens expire. Direct writes may still leave the current destination file incomplete after interruption.
  • The interface is sandboxed and isolated from Node.js. A limited preload bridge validates calls from the application's main frame. Remote navigation, popup windows, and permission requests are denied.
  • The app does not provide filesystem snapshots or a guarantee against sudden power loss, physical drive failure, or another local process racing changes during a backup.

Network and local privacy

Backup content is not uploaded by the app. If automatic checks are enabled, the updater contacts GitHub and its download infrastructure. New installations check and download updates automatically, then wait for manual installation; users can change these options in Settings. Network services receive ordinary request metadata such as IP addresses. Fonts and visual assets are bundled locally.

Settings and Activity stay in the current user's application-data directory. Logs include Robocopy commands and may contain personal file paths. Review and redact them before sharing. The uninstaller can remove app settings and logs; it does not remove backup sources or destinations.

Report a vulnerability

Use private vulnerability reporting. Include the affected version and a minimal reproduction using non-sensitive test files. Avoid publishing personal file paths or exploit details in a public issue.
